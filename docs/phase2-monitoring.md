## Docker Network
The monitoring stack joins the existing application network. Since the application deployment now uses the `-p farmer` flag in Jenkins, the stable network name is:
**`farmer_default`**

## Verification Steps

### 1. Verify Prometheus Targets
- Open `http://<EC2_IP>:9090/targets` in your browser.
- Verify that `backend`, `ml_service`, `node_exporter`, and `cadvisor` are all in the **UP** state.

### 2. Verify Grafana Dashboard
- Open `http://<EC2_IP>:3000` in your browser.
- No login is required (Anonymous Auth is enabled as Admin).
- Navigate to **Dashboards -> Farmer Helper Monitoring**.

### 3. Verification per Panel
Generate traffic by running `python monitoring/traffic.py` on the EC2 instance, then verify each panel:

- **Service Uptime (Up/Down):** Should show 1 for backend, ml_service, node_exporter, and cadvisor.
- **Request Rate (Backend):** Should show spikes as the traffic script hits the backend API endpoints (`/crop`, `/weather`, `/auth/login`).
- **Request Rate (ML Service):** Should show spikes corresponding to the ML service routes being called.
- **Error Rate (Backend & ML):** Should show a steady stream of 4xx/5xx errors due to the bad requests generated by the traffic script.
- **P95 Latency (Backend & ML):** Should show a graph of response times. The ML endpoints will typically have higher latency due to inference time.
- **CPU Usage:** Should show current CPU utilization of the EC2 instance (gathered via node_exporter).
- **Memory Usage:** Should show current Memory utilization (gathered via node_exporter).

### 4. Start Traffic Script (Optional)
To generate continuous traffic to visualize data on the dashboard:
```bash
# On the EC2 host
cd /home/ubuntu/app/monitoring
python3 traffic.py
```
*(Press Ctrl+C to stop)*
